# Sony SR2 white balance follow-up — 2026-10-27

Agent: Codex. Base: `142f7f7`; branch `codex/sony-sr2-white-balance`.
This follows HANDOFF item 7 and the [emulator report](2026-10-27-emulator.md).

## Cause and change

The decoder required raw-IFD `0x7313` before reaching the private SR2 directory, which it already decrypts for
its colour matrix. Older files can hold the as-shot white balance only in that directory.

The reader now decrypts it once and tries: raw-IFD RGGB `0x7313`, SR2 RGGB `0x7313`, then SR2 GRBG `0x7303`.
It normalises red/blue by the first green in the stored layout, preserving the existing RGGB calculation.
The legacy raw-IFD eligibility is unchanged (four levels and positive first green, including its accepted
finite zero/negative red/blue gains). New SR2 candidates require four positive levels; absent, wrong-size or
non-positive SR2 values fall through to the next source, then fail with IOException if none are usable. Damaged TIFF ranges still fail; values are not guessed.
Colour matrix, sensor decompression, lens correction and the renderer are otherwise unchanged.

The tag identities/order were checked against the primary
[ExifTool Sony SR2SubIFD definitions](https://github.com/exiftool/exiftool/blob/master/lib/Image/ExifTool/Sony.pm#L10384).
No code from another decoder was copied and no dependency was added.

## Evidence

- Before implementation, four new synthetic cases failed with `Missing white balance`. After the fix all thirteen
  SonyArwTest cases pass, with RawRendererTest. New fixtures cover SR2 RGGB, GRBG order (distinct green levels),
  raw/SR2 precedence, invalid values/fallback and missing/invalid failure. SR2 colour-matrix reading is also asserted.
- A disposable JVM probe read the already downloaded public samples from [rawsamples.ch](https://rawsamples.ch/index.php/en/sony).
  No sample was edited or committed; repository fixtures are generated synthetic bytes.
- ILCE-7M2: raw `0x7313` absent; decrypted SR2 `0x7313` is `[2208, 1024, 1024, 2016]`. Before: IOException.
  After: sensor 6048×4024, WB `[2.15625, 1, 1.96875]`, RawDeveloper preview 756×503 with nonzero pixels.
- ILCE-7RM2: raw WB absent, but `0xC634` points to 49576, inside the embedded JPEG's byte range (48558–469799).
  Parsing that location as a locator fails TIFF range validation. A fresh download is byte-identical:
  SHA-256 `6347bc46ffb1c05b968c4e7cdc1dad7dd95c7aeddac9c77cae6f4f3ed870c5ee`.
  This sample still fails with IOException. The original report's claim that both samples are merely missing
  raw-IFD WB was too broad: the 7RM2 sample's private locator cannot be used as-is.
