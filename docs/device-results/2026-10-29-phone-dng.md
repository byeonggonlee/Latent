# Open Camera and MotionCam DNG compatibility — 2026-10-29

Agent: Codex. Base: `186ff30`; branch `codex/phone-dng`, [PR #52](https://github.com/byeonggonlee/Latent/pull/52).
This addresses HANDOFF §0 item 2 / roadmap 0.2.0 item 15. PR #51 remains separate for the owner to judge.

## Result and scope

The four public files below decode and develop. On the API 36 ARM64 emulator, all four produce a thumbnail, an
unedited preview and a full-resolution JPEG. The initial validation at `c99588e` reproduced no production defect;
Claude's review then found the pre-existing wrong OpcodeList3 tag. This PR now corrects that tag in the reader
and fixtures. The geometry engine, colour calculation, clipping policy and dependencies are unchanged.

The deliverable is the tag fix and repeatable compatibility coverage: three hermetic tests, four optional
public-sample tests and four optional Android tests. This is not a physical-phone colour judgement, exact
camera-JPEG matching or a claim that every DNG produced by either app is supported.

## Metadata and existing processing

All four are uncompressed, single-plane Bayer DNGs with stored BitsPerSample 16 and Orientation 1. In particular,
the MotionCam source names describe capture modes; they do not justify assuming a 10-/12-bit storage white level.

- Pixel 2 XL: stored 4032×3032, active area `(top=8, left=0, bottom=3032, right=4032)`, BGGR; four fractional
  black levels `[63.93, 63.81, 63.75, 63.87]`, white 1023. AsShotNeutral `[0.5390625, 1, 0.5625]` gives
  WB `[1.8550725, 1, 1.7777778]`. Four optional OpcodeList2 GainMaps cover the four Bayer positions.
- Honor 6A: stored/active 4208×3120, GRBG; black 64, white 1023. AsShotNeutral
  `[0.5390625, 1.0078125, 0.5625]` gives WB `[1.8695652, 1, 1.7916667]`: green must be normalised too.
  Four optional OpcodeList2 GainMaps cover the four Bayer positions.
- MotionCam 10-bit capture: stored/active 4080×2288, GBRG; black 1024, white 65535;
  WB `[2.0940695, 1, 1.4905386]`. No opcode lists.
- MotionCam 12-bit DCG capture: stored/active 4080×2288, GBRG; black 4093, white 65535;
  WB `[2.1200829, 1, 1.4712644]`. No opcode lists.

Neither MotionCam file has OpcodeList3. Both Open Camera files store a four-byte empty OpcodeList3 at standard
tag 51022 (`0xC74E`), so no sampled file supplies non-empty geometry. The initial assertion that all four lacked
OpcodeList3 looked at the wrong tag and is superseded by this recheck. The Open Camera gain maps have pitch 2 in
both dimensions; they address different positions within the one-plane mosaic, not separate RGB sample planes.

**Crop limit preserved:** Dng currently moves the crop origin to a red photosite and uses even extents. The Pixel's
requested raw origin `(8,16)` becomes `(9,17)`, size 4016×3008; Honor's `(8,8)` becomes `(9,8)`, size 4192×3104.
MotionCam has no DefaultCrop tags, so its full active area becomes `(0,1)`, size 4080×2286: two rows are omitted.
Tests record this existing policy, not pixel-exact preservation of the writers' requested framing. Preserving the
exact crop would require carrying Bayer phase through this seam instead; this validation does not implement that
change or borrow the unmerged PR #51 seam work.

## Claude review follow-up: standard OpcodeList3 tag

[Claude Opus 5.5's review](https://github.com/byeonggonlee/Latent/pull/52#pullrequestreview-5693927974) found P2:
both `Dng.kt` and the synthetic fixture used `0xC742` for OpcodeList3, so tests agreed with the same mistake and
the production reader missed supported geometry in real DNGs. The
[Adobe DNG 1.7.1 specification, page 58](https://helpx.adobe.com/content/dam/help/en/camera-raw/digital-negative/jcr_content/root/content/flex/items/position/position-par/download_section_733958301/download-1/DNG_Spec_1_7_1_0.pdf)
defines OpcodeList3 as decimal **51022**, hexadecimal **`0xC74E`**. It is not consecutive with OpcodeList1/2.

- Both synthetic fixture entries were corrected first. With the reader unchanged, 13 warp-related tests failed,
  including a new test pinning decimal tag 51022 and a non-identity warp in Android/Adobe mosaic and linear files.
- Correcting only the production tag makes all 135 raw cases pass, with two unrelated external-sample skips.
  The existing geometry, toggle, orientation, ordering, malformed-metadata and plane/matrix tests now exercise the
  standard tag. No threshold was relaxed.
- The four public-file tests now check the real tag directly: four zero bytes for Open Camera's empty list,
  absent for MotionCam, and no `0xC742` in any file. Empty lists expose no warp, as expected.
- Earlier private Galaxy claims in DEVICE_CHECKS, ROADMAP and PR #17's plan are marked unverified rather than
  repeated. The two known inputs (`20261022_103021.dng`, `20261022_103110.dng`) could not be found in the retained
  sample/worktree directories or by indexed filename search. Rechecking their standard tags remains pending;
  no new claim about their geometry is made.

The reviewer covered this exact proposed production correction. A follow-up review is requested for the completed
change and the updated evidence. This is a bug fix to reading metadata, not a new colour profile or rendering look.

Final validation after the tag fix: `testDebugUnitTest lintDebug lintRelease assembleDebugAndroidTest assembleDebug
--offline` succeeds with the public sample directory set: **832 JVM cases**, zero failures/errors, four unrelated
external-sample skips. Both Lints have zero errors and nine warnings; schema/whitespace checks are clean. Newly
built APKs were installed with `-r -t`, and all **4 emulator cases pass again**, 40.127 s total. This is the same
thumbnail/preview/full-export coverage as the initial run, not a real non-empty-warp/device-colour comparison.

## Reproduction

Download the four originals outside the repository and use the local aliases above. Verify the hashes first.

```bash
PHONE_DNG_SAMPLE_DIR=/path/to/public-phone-dngs \
  ./gradlew testDebugUnitTest --tests 'com.byeonggon.latent.raw.PhoneDng*'
```

Copy those inputs to a dedicated directory readable by Latent Debug (for example its `cache/phone-dng-test`), then:

```bash
adb -s emulator-5554 install -r -t app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w -r \
  -e class com.byeonggon.latent.raw.PhoneDngOnDeviceTest \
  -e phoneDngDir /data/user/0/com.latentimage.latent.debug/cache/phone-dng-test \
  com.latentimage.latent.debug.test/androidx.test.runner.AndroidJUnitRunner
```
