# Rediscover the trash after reinstall

Owner-authorized scope, 2026-11-18: implement one small task at a time, starting with the existing 0.2.0 item 10. Reuse the current trash UI, layout and restore/empty operations; no schema or backup format change.

## Approaches

Reconstructing the database from external backups would require a backup and still leaves orphan files invisible. Moving leftovers into the active library would undo the owner's deletion. The chosen approach registers recoverable on-disk trash bundles in the existing trash table without moving them; the owner chooses restore or empty. This implements the previously agreed rediscovery approach.

## Behavior and preservation

- During library refresh with storage access, inspect only immediate numeric trash bundle directories (and collision suffixes generated by this app). Use the granted-folder provider when direct listing is unavailable.
- Recover only an unambiguous bundle with one supported main media file and optional matching `original-<name>` / XMP companions. Leave ambiguous bundles and unknown files alone. Skip any bundle already represented in the database; rescanning is idempotent.
- Use existing safe ownership takeover before reading a file left by another installation. Keep its bytes and location. Metadata comes from the file; unknown capture time uses its timestamp or discovery time. Original DB-only edits/ratings/albums cannot be reconstructed.
- The original restore path is lost. Restore recovered files into the library's normal capture-date folder, choosing a free name at restore time. Keep original/XMP companions attached.
- A recovered row uses a documented never-expire marker in the existing nullable trash timestamp. No schema change. Only explicit restore/empty removes these recovered bundles; existing ordinary-trash expiry is unchanged.
- New trash entries must never reuse an occupied orphan bundle directory. Preserve unexpected files on restore and verify deletion before dropping a row on explicit empty.
- Do not follow symlinks outside the trash or interpret sidecar/original-only/partial bundles as independent photos. No full-cache wipe, uninstall or data clear.
